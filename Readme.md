# WhatsApp Chatbot Backend (Flask + WhatsApp Cloud API + Gemini)

## Overview
This project is a backend automation system for WhatsApp using **Python Flask**, the
**WhatsApp Cloud API**, and **Google Gemini**. It receives customer messages on a
webhook and replies with AI-generated support answers instead of a static echo.

Sensitive credentials are handled via environment variables so anyone can run their
own instance safely.

---

## Features
- Flask server acting as a **webhook** for WhatsApp messages.
- Webhook **verification** with a custom verify token.
- **HMAC-SHA256 signature verification** (`X-Hub-Signature-256`) on every incoming POST.
- AI replies generated by **Gemini** (`gemini-3.5-flash-lite`).
- **Short-term memory**: the last 10 messages per sender are used as chat context.
- **Typing indicator** + read receipt while the answer is generated.
- **Background processing** so the webhook returns instantly (no Meta timeouts).
- **Long replies** are split into multiple messages (WhatsApp's ~4096-char limit).
- A polite notice for **non-text messages** (images, audio, documents, ...).
- Friendly **fallback message** when the LLM fails.
- **Human handoff**: the bot pauses itself and notifies an admin, who can resume it.

## Project Setup

### 1. Clone the repository
```bash
git clone https://github.com/Saif-Ali-109/Whatsapp_Chatbot.git
cd Whatsapp_Chatbot
```

### 2. Install dependencies
```bash
uv sync
```

### 3. Set up your `.env` file
Copy the template and fill in your values:
```bash
cp .env.example .env
```
```env
ACCESS_TOKEN=your_whatsapp_access_token_here
PHONE_NUMBER_ID=your_whatsapp_number_id_here
VERIFY_TOKEN=your_secret_verify_token_here
APP_SECRET=your_meta_app_secret_here
GEMINI_API_KEY=your_gemini_api_key_here
ADMIN_WHATSAPP_NUMBER=
```
> **Important:** Never share or commit your `.env` file.

### 4. Run the server
```bash
uv run main.py
```
Server runs on `http://127.0.0.1:5000`.

### 5. Expose it locally with ngrok
```bash
ngrok http 5000
```
Copy the generated **Forwarding URL** as your WhatsApp webhook URL.

### 6. Configure the webhook in Meta Developer
1. Go to [Meta Developer Dashboard](https://developers.facebook.com/apps) → Your App → WhatsApp → Configuration.
2. Set the **Callback URL** to `https://<your-ngrok-url>/whatsapp-webhook`.
3. Enter your **Verify token** (the same `VERIFY_TOKEN` from `.env`).
4. Subscribe to the **messages** field and verify the webhook.

## Configuration Reference

| Variable | Required | Default | Purpose |
|---|---|---|---|
| `ACCESS_TOKEN` | yes | — | WhatsApp Cloud API token |
| `PHONE_NUMBER_ID` | yes | — | WhatsApp business phone number ID |
| `VERIFY_TOKEN` | yes | — | Webhook verification string |
| `GEMINI_API_KEY` | yes | — | Google Gemini API key |
| `APP_SECRET` | yes | — | Meta app secret for signature checks |
| `ADMIN_WHATSAPP_NUMBER` | no | — | Handoff alerts + admin commands |
| `GEMINI_MODEL` | no | `gemini-3.5-flash-lite` | Gemini model id |
| `HISTORY_LIMIT` | no | `10` | Messages kept per sender |
| `GRAPH_API_VERSION` | no | `v24.0` | Graph API version |
| `SYSTEM_PROMPT` | no | built-in | Override the assistant persona |
| `FALLBACK_MESSAGE` | no | built-in | Sent when the LLM fails |
| `NON_TEXT_NOTICE` | no | built-in | Sent for non-text messages |
| `VALIDATE_SIGNATURE` | no | `true` | Disable only for local testing |
| `PORT` | no | `5000` | Server port |

## How it Works
1. WhatsApp sends incoming messages to `POST /whatsapp-webhook`.
2. The server verifies the signature, then returns `200` immediately.
3. For text messages it shows a typing indicator and asks Gemini for a reply,
   including the last 10 messages of that user's history.
4. The reply is split if needed and sent back to the sender.
5. Non-text messages receive a friendly "text only" notice.
6. If Gemini fails, the sender receives the fallback message.

### Human handoff
When a customer asks for a human (or the model decides it needs one):
- The bot sends its reply and then **pauses auto-replies** for that customer.
- If `ADMIN_WHATSAPP_NUMBER` is set, the admin receives a notification with the
  recent conversation.
- The admin can manage conversations by messaging the business number:
  - `resume <number>` — let the bot handle the customer again
  - `pause <number>` — stop auto-replies for a customer
  - `status <number>` — check whether a customer is paused

## Testing
```bash
uv run pytest
```
The suite covers signature verification, message chunking, session memory, the LLM
wrapper (Gemini mocked), and the full webhook dispatch logic. No network required.

---

## Notes for Users
- You must create your own `.env` with your own credentials.
- Only **text** messages get AI replies; other types get a notice.
- Conversation memory is **in-memory** and resets when the server restarts.
- `.env` and `spec.md` are gitignored and must never be published.
